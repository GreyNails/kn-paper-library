00:06:23–00:07:18在论文的第二章相关工作当中，作者系统的回归了当前大圆模型在推理能力提升方面的三种主要的技术路径，并逐一的分析了它们的局限性。第一种是测试时的扩展，就是通过增加模型在推理阶段的生成的长度或是深度来提升性能。比如说 OpenAI 的 o1 模型和 DeepSync RE 都用了这种方法。通过生成更长的推理链来提高准确率。但是这种方法的核心问题就是由于自回归模型顺序生成的特性，生成的长度增加会导致延迟的线性增加，难以在实际的应用当中拓展。第二种的路径是非自回归模型，比如像扩散模型和一致性模型，它们通过并行的生成多个 token 来提升的效率。

00:07:19–00:08:11然而,这些方法往往忽略了 token 之间的逻辑依赖关系导致生成的内容缺乏连贯性另外,扩散模型通常需要多次的迭代去噪计算的开销巨大且难以处理复杂的推理任务第三种是借助外部工具或模型来实现并行比如像蒙多卡罗素搜索或者是思维树这些方法虽然能够实现一定程度上的并行搜索，但由于依赖外部的模块进行任务分解和结果验证，那就会导致中间的推理状态在模块间传递的时候丢失，严重影响推理的完整性和效率。相比之下，Motivus 的创新之处就在于它是首次将 MapReduce 的结构内嵌于生成模型的内部。

00:08:36–00:09:24作者分析了上千条推理列，发现 98%都包含可以并行处理的部分，比如同时分析多个案例，尝试多个解法。但问题是，模型自己并不知道这些步骤可以并行。通过实验，作者发现即使我们告诉模型你可以并行，它也做不到。这就引出一个问题，我们能不能设计一个模型，让它有意识的并行思考。在论文的第三章中，作者提出了一个关键问题：自回归语言模型在生成过程中是否存在可以被并行处理的逻辑结构？为了回答这个问题，作者对 S1K-1 以数据集中的常恋推理轨迹进行了深入分析，结果令人惊讶。

00:09:24–00:09:52超过 98%的推理链中都存在可以并行处理的逻辑结构。作者将这些并行结构分为两类：集体型和选择型。集体型结构指的是多个子任务可以并行执行，最终合并结果，例如同时分析多个案例或计算多个子表达式。选择型结构则是指模型在多个候选路径中选择一个继续推进，例如尝试不同的解题方法或假设。

00:09:53–00:10:33Video2 清晰地展示了这两种结构的典型示例。例如在解决一个数学问题时，模型可能会同时尝试两种不同的解法选择型，或者在计算一个复杂表达式时分别计算多个子表达式集体型。这些结构在推理链中频繁出现，说明自回归模型在生成过程中确实存在大量的并行潜力。然而，尽管这些并行结构广泛存在，自回归模型却无法主动识别或控制它们。作者通过 Prompting 和 Probing 实验验证了这一点。在 Prompting 实验中，即使明确提示模型可以并行思考，模型仍然无法生成并行结构。

00:10:33–00:11:23在 Probing 实验中，作者训练了一个分类器来识别并行结构的起始位置，但分类器的准确率接近随机猜测，说明模型在隐藏状态中也缺乏对并行结构的显式表示。这一发现具有重要的启示，虽然自回归模型在训练过程中学习到了并行结构的生成模式，但它们并不具备显式的并行意识，这就引出了一个关键问题我们能否设计一种新的模型架构，让模型能够主动识别、控制并利用这些并行结构？这正是 Multiverse 模型设计的出发点。这就是 Multiverse 的核心设计了，它把生成过程分成了三个阶段：MapProcess 和 Reduce。你可以把它想象成一个任务流水线，先分解任务，再并行处理，最后合并结果。
